This module contains the six shared curriculum ORM models. It uses the existing
SQLAlchemy `Base`, UUID handling and constraint naming. Alembic imports these
models in `backend/alembic/env.py`. Batch 1 introduced no API, Pydantic schemas,

Existing Game, Quiz and Tutor `concept_id` columns remain unchanged. The public
key `math_concepts.concept_id` is `VARCHAR(100)`, compatible with their string
contracts; existing identifiers are not normalized or constrained yet.

## Columns

All columns are required unless marked **nullable** below. Every table includes
`created_at` and `updated_at`: required timezone-aware timestamps with database
default `now()`. ORM updates also advance `updated_at`; raw SQL writers must set
it explicitly. No update trigger is installed.

Every `id` below is a UUID primary key generated by the ORM with `uuid.uuid4`.
Raw SQL writers supply UUIDs explicitly, matching existing project conventions.
`math_concepts` instead has the stable string primary key and no UUID `id`.

| Table | Columns in addition to the timestamps |
| --- | --- |
| `curriculum_versions` | `id UUID PK`; `version_code VARCHAR(100) UNIQUE`; `version_name VARCHAR(255)`; `grade_level INTEGER DEFAULT 10`; `subject_code VARCHAR(100) DEFAULT 'mathematics'`; **nullable** `description TEXT`, `start_year INTEGER`, `end_year INTEGER`; `status VARCHAR(20) DEFAULT 'draft'`. |
| `curriculum_units` | `id UUID PK`; `curriculum_version_id UUID FK`; `unit_code VARCHAR(100)`; **nullable** `unit_name_en VARCHAR(255)`, `unit_name_si VARCHAR(255)`, `description TEXT`; `sequence_order INTEGER`; `status VARCHAR(20) DEFAULT 'active'`. |
| `math_concepts` | `concept_id VARCHAR(100) PK`; `name_en VARCHAR(255)`; **nullable** `name_si VARCHAR(255)`, `description_en TEXT`, `description_si TEXT`; `concept_type VARCHAR(20)`; `status VARCHAR(20) DEFAULT 'active'`. |
| `curriculum_concepts` | `id UUID PK`; `curriculum_version_id UUID FK`; `unit_id UUID` (part of composite FK); `concept_id VARCHAR(100) FK`; `sequence_order INTEGER`; **nullable** `learning_objective TEXT`; `is_mandatory BOOLEAN DEFAULT true`; `status VARCHAR(20) DEFAULT 'active'`. |
| `curriculum_documents` | `id UUID PK`; `curriculum_version_id UUID FK`; `document_code VARCHAR(100)`; `title VARCHAR(255)`; `language_code VARCHAR(2)`; `document_type VARCHAR(20)`; `file_path TEXT`; **nullable** `publisher VARCHAR(255)`, `publication_year INTEGER`, `description TEXT`; `status VARCHAR(20) DEFAULT 'active'`. |
| `concept_content` | `id UUID PK`; `curriculum_concept_id UUID FK`; `language_code VARCHAR(2)`; `content_type VARCHAR(30)`; **nullable** `title VARCHAR(255)`; `content TEXT`; **nullable** `source_document_id UUID FK`, `source_page_start INTEGER`, `source_page_end INTEGER`; `content_version INTEGER DEFAULT 1`; `status VARCHAR(20) DEFAULT 'draft'`. |

The defaults shown are database defaults as well as ORM defaults.

## Constraints and relationships

- Version: unique `version_code`; positive grade; when both years are present,
  `end_year >= start_year`; status `draft/active/archived`.
- Unit: FK to version, `ON DELETE RESTRICT`; unique `(curriculum_version_id,
  unit_code)`; unique `(curriculum_version_id, id)` for the composite mapping FK;
  nonnegative sequence order; status `active/inactive/archived`.
- Stable concept: type `topic/subtopic/skill/prerequisite`; status
  `active/inactive/archived`.
- Mapping: FK to version; FK to stable concept; composite FK
  `(curriculum_version_id, unit_id)` to `curriculum_units(curriculum_version_id,
  id)`. All use `ON DELETE RESTRICT`. This rejects mappings whose unit belongs
  to a different version. Unique `(curriculum_version_id, unit_id, concept_id)`;
  nonnegative sequence order; status `active/inactive/archived`.
- Document: FK to version, `ON DELETE RESTRICT`; unique `(curriculum_version_id,
  document_code, language_code)`; language `si/en`; type
  `textbook/syllabus/teacher_guide/lesson_pdf/other`; status
  `active/inactive/archived`. Only paths/metadata are stored, never PDF binaries.
- Content: required FK to mapping, `ON DELETE RESTRICT`; optional FK to document,
  `ON DELETE SET NULL` (deleting a document preserves content and page history);
  language `si/en`; type `definition/explanation/worked_example/formula/
  misconception/hint/summary/learning_objective/other`; status
  `draft/reviewed/approved/archived`; positive content version; positive page
  values when supplied and `source_page_end >= source_page_start` when both exist.

Prefer archiving documents to retain their source metadata. Content versions are
positive integers; automatic revision creation or immutable history is not
implemented. Future APIs/ingestion must validate that a content piece and its
source document belong to the intended curriculum version and language.

## Indexes

Eight explicit indexes:

- `ix_curriculum_concepts_unit_id`
- `ix_curriculum_concepts_concept_id`
- `ix_curriculum_documents_language_code`
- `ix_concept_content_curriculum_concept_id`
- `ix_concept_content_language_code`
- `ix_concept_content_content_type`
- `ix_concept_content_status`
- `ix_concept_content_source_document_id`

The version-leading unique indexes on units, mappings and documents already
support lookups by `curriculum_version_id`; duplicate single-column indexes are
unnecessary. Primary keys and uniqueness constraints also create backing indexes.

## Tests

From `backend/` run `python -m pytest -q` and `python -m ruff check .`.
`tests/test_curriculum_models.py` runs the actual new migration with SQLite
foreign-key enforcement, then exercises the ORM against those tables.

For PostgreSQL, explicitly supply disposable **local** databases:

- `CURRICULUM_TEST_DATABASE_URL`: local database named `curriculum_test_*` for
  the same constraint/ORM tests on PostgreSQL. The fixture creates/removes the
  six curriculum tables and must not point to a database you use for real work.
- `CURRICULUM_MIGRATION_TEST_DATABASE_URL`: a separate empty local database named
  `curriculum_test_*`. The migration test builds 0001–0005, stores synthetic Game
  data, upgrades to 0006, compares curriculum metadata with the models, verifies
  old schemas/data are unchanged, then exercises 0006 downgrade/re-upgrade.

These opt-in tests reject nonlocal database URLs and never use the application's
`DATABASE_URL`. The full-chain test is skipped when its test URL is not supplied.
Batch 2 introduces source-traceable draft curriculum data through a separate
seed utility. See [Equations curriculum seed](../../../scripts/EQUATIONS_CURRICULUM.md)
for commands, the manifest, source limitations, page conventions and verification.
